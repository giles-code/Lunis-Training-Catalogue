## Aim and Purpose

The aim of this workshop is to build participants' understanding of how open banking access rights operate under PSD2/PSD3, and the supervisory considerations for account information and payment initiation service providers.

## Intended Audience

Junior to mid-level supervisors working in payment services supervision.

## Learning Objectives

- Explain the open banking access rights established under PSD2
- Describe the roles of account information service providers and payment initiation service providers
- Assess strong customer authentication requirements in an open banking context
- Evaluate API access quality and its supervisory relevance
- Formulate a supervisory assessment of an open banking access arrangement

## Syllabus

**Session 1: Open banking access rights (09:30–10:45)**
*Objective: Explain open banking access rights*
- The rationale for open banking and third-party access rights
- Account information services and payment initiation services distinguished
- Consent and data-sharing frameworks underpinning open banking
- Market development of open banking use cases
Activities:
- Facilitated discussion: open banking developments participants have observed

**Session 2: Strong customer authentication and API access (11:00–12:30)**
*Objective: Assess SCA requirements and evaluate API access quality*
- Strong customer authentication requirements and their application to open banking
- API access quality: reliability, availability, and the 'obstacle' prohibition
- Common friction points between account-servicing and third-party providers
- Supervisory relevance of API performance data
Activities:
- Group exercise: assess a sample API access arrangement for quality and compliance

**Session 3: Application to a case study (13:30–14:45)**
*Objective: Formulate a supervisory assessment*
- Bringing access rights, SCA, and API quality assessment together
- Case study: an open banking access dispute or quality concern
Activities:
- Case study: formulate a supervisory assessment of an open banking access arrangement

**Session 4: Wrap-up and key takeaways (14:45–15:00)**
*Objective: Consolidate learning*
- Recap: access rights, SCA, API access quality
Activities:
- Reflection and discussion
- Q&A

## Structure and Format

Proposed as a half-day workshop (approx. 3.5 hours substantive content), comprising 4 sessions:
- Session 1: Open banking access rights (09:30–10:45)
- Session 2: Strong customer authentication and API access (11:00–12:30)
- Session 3: Application to a case study (13:30–14:45)
- Session 4: Wrap-up and key takeaways (14:45–15:00)

**Key Takeaways**
- Open banking access rights only deliver real value if API access quality genuinely supports third-party providers
- Strong customer authentication must be implemented in a way that does not create unreasonable obstacles to legitimate access
- Friction between account-servicing and third-party providers is a recurring supervisory theme in open banking markets
